## [3.0.6] - 2026-08-26

### 🔒 Безпека / hardening

- **Runtime-образ `ubuntu:24.04` → `alpine:3.22`** (~75 МБ → ~15 МБ): менша surface area для патчів, як і обіцяно в CHANGELOG v3.0.0. `busybox` надає `ping`/`wget`; `setcap cap_net_raw=ep /bin/ping` дозволяє ICMP-перевірки від non-root користувача. Distroless не підходить — ping-перевірки використовують зовнішній бінарник.
- **systemd-юніт hardening** в install.sh: `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`, `PrivateDevices`, захист kernel/control-group інтерфейсів, `MemoryDenyWriteExecute`, обмеження address families; запис дозволено лише у DATA_DIR/LOG_DIR.
- **telegraf-контейнер**: `read_only`, `cap_drop: ALL`, `no-new-privileges`.
- **CI**: додано блок `permissions: contents: read`, **govulncheck** та **golangci-lint**.

### Інше
- Додано **Dependabot** (gomod, github-actions, docker — щотижня).
- Версія синхронізована по всьому репозиторію → **3.0.6**.

## [3.0.4] - 2026-08-26

### 🐛 Виправлення

- **Полагоджено Docker HEALTHCHECK.** У фінальному образі був відсутній `wget`, яким користуються healthcheck у Dockerfile та docker-compose — контейнер завжди вважався unhealthy. `wget` додано до встановлюваних пакетів.
- **Прибрано передбачуваний fallback-пароль адміна в install.sh.** Якщо генерація пароля з `/dev/urandom` не вдалась, використовувався детермінований `PyMon$(date +%s)`. Тепер інсталятор завершується з помилкою з підказкою задати `PYMON_ADMIN_PASSWORD`.
- **Виправлено telegraf-пайплайн у docker-compose.** `outputs.file` писав у `/var/log/telegraf` всередині контейнера без монтування — дані губились після перезапуску й були недоступні ззовні. Додано named volume `telegraf-data:/var/log/telegraf`.

### Інше
- Версія синхронізована по всьому репозиторію → **3.0.4** (Dockerfile LABEL мав 3.1.0, решта — 3.0.3).

## [3.0.3] - 2026-08-12

### 🐛 Виправлення (production audit round)

#### Функціональність (критичне)
- **Дашборд знову працює під CSP.** Content-Security-Policy з `script-src 'self'` блокував Chart.js, Lucide та Google Fonts із CDN — інтерфейс відкривався без іконок і графіків. До CSP додано `https://cdn.jsdelivr.net`, `https://unpkg.com`, `https://fonts.googleapis.com`, `https://fonts.gstatic.com` (inline-скрипти та inline-обробники як і раніше заборонені).
- **Звіт сервера (`/api/v1/reports/...`) знову рендериться.** Inline `<script>` із даними графіків блокувався глобальним CSP. Тепер звіт встановлює власний CSP із випадковим nonce для рівно одного inline-скрипта; кнопка друку переведена на `addEventListener` (inline `onclick` заборонений CSP).
- **`/settings/config/export` більше не ламає сповіщення.** Раніше ендпоінт записував `"***REDACTED***"` у живий об'єкт конфіга в пам'яті — після експорту Telegram та Email-алерти переставали працювати. Тепер конфіг глибоко копіюється (`Config.Clone()`), редоктяться лише секрети копії.
- **Витік webhook URL у експорті конфіга.** Slack/Discord/Teams `webhook_url` тепер редоктяться (як і bot token / SMTP пароль).

#### Безпека
- **Захист від Prometheus-ін'єкції у `/metrics`.** `POST /api/v1/metrics` (доступний будь-якому авторизованому користувачу) дозволяв ім'я метрики з перенесенням рядка — інжектилось у публічний Prometheus-експорт. Додано валідацію імені метрики (граматика `[a-zA-Z_:][a-zA-Z0-9_:]*`), довжин name/help/labels, плюс defense-in-depth санітизація на виводі.
- **Cardinality-ліміт in-memory registry.** `MetricRegistry` більше не росте безкінечно — максимум 5000 унікальних серій (антивот DoS через push).
- **Rate-limit більше не обходиться через `X-Forwarded-For`.** Заголовок приймається лише від локальних/приватних проксі; інакше використовується реальний адресат з'єднання.
- **SSRF-guard для сервісів:** `userinfo` у URL (`http://user@127.0.0.1/`) більше не обходить перевірку хоста.
- **Panics у `PUT /api/v1/servers/{id}`.** Небезпечні type assertions (`v.(string)`, `v.(float64)`) замінені на безпечні type switches з валідацією (порт 1–65535, позитивні інтервали).

#### Коректність даних
- **Timestamp-порівняння у SQLite.** Збережені часові мітки формату `2006-01-02T15:04:05` порівнювались із `datetime('now', ...)` (формат із пробілом) — через різницю роздільника усі рядки поточного дня влучали у вікно (історія віддавала зайві години, retention тримав дані до +24 год). Cutoff тепер обчислюється в Go у тому самому форматі — порівняння коректне, індекси використовуються.

#### Інше
- Версія бінарника синхронізована (було 3.0.1 замість v3.0.2) → **3.0.3**; оновлено README, Dockerfile, docker-compose, SW-кеш.
- docker-compose більше не посилається на непублікований `ghcr.io/ajjs1ajjs/Monitoring:3.0.0`.
- Прибрано dead code (`var _ = strings.TrimSpace`, `var _ = time.Now`).

## [3.0.0] - 2026-08-06

### Змінено (повне переписування Python → Go)

- **Бекенд переписано з Python (FastAPI) на Go 1.25** — один статичний бінар, нижче споживання RAM/CPU, миттєвий старт.
- **SQLite через `modernc.org/sqlite`** (pure-Go, без CGO) — той самий WAL-режим, схема БД ідентична (можна підключити існуючу базу v2.x).
- **Той самий REST API + WebSocket контракт** — фронтенд перевикористовується як embedded assets через `go:embed`.
- **Моніторинг**: ScrapeManager (node_exporter/windows_exporter) та ServiceChecker (http/ping/ssl) як горутини; офіційний Prometheus-парсер `prometheus/common`.
- **Виправлено відомі баги**: додано реальний Slack-канал сповіщень; додано видалення API-ключа (`DELETE /api/v1/auth/api-keys/{id}`).
- **CLI**: `pymon server`, `pymon reset-admin`, `pymon --version`.
- **Docker**: multi-stage Go → scratch/alpine, healthcheck через wget.
- **CI**: Go vet + `go test -race` + Docker smoke-тест.
- **Тести**: config, моніторинговий парсер (Linux/Windows), storage (CRUD, backup/restore, uptime), API smoke-тести (auth, RBAC, сервери, prometheus-export).

### Сумісність

- Схема БД і ключі даних не змінюються — дані v2.x переносяться без міграції.
- Клієнтський API і формати відповідей збережені.

### 🧹 Best-practice hardening (закриття решти пунктів аудиту)

- **Піновано `telegraf`** у `docker-compose.yml` → `telegraf:1.39.2` (замість `latest`).

- **Офіційний Prometheus-парсер.** Ручний розбір рядків у `_parse_metrics` замінено на `prometheus_client.parser` — коректно обробляє label-значення з комами, екрануванням, timestamp та family histogram/summary.

- **Видалено мертві `pymon/processors/*` та `services/metric_processor.py`** (не використовувалися в пайплайні).

## [2.3.2] - 2026-08-06

### 🔒 Безпека
- **CSP без `unsafe-inline` у `script-src`.** Усі інлайн-обробники (`onclick`/`onchange`/`oninput`) у дашборді та логіні замінено на делегування подій через `data-click`/`data-change`/`data-input` + `data-args`; inline-скрипт логіну перенесено в `static/js/login.js`. Новий CSP: `script-src 'self' https://cdn.jsdelivr.net https://unpkg.com` (без wildcard `https:`, без `unsafe-inline`) — це усуває головний залишковий XSS-вектор після попереднього екранування.
- Прибрано дубльовану (зламану) форму створення користувача з дублюванням `id` у `dashboard.html`.

#### Продуктивність
- **Даунсемплінг історії метрик.** `/servers/history` і `/servers/{id}/history(-detail)` повертають одну точку на часовий бакет (хвилина; погодинний — для діапазонів ≥7 днів) через `ROW_NUMBER() OVER (...)`. Замість сотень тисяч рядків у пам'яті — обмежена кількість точок; `disk_info` зберігається (останній рядок бакета).

#### Якість
- `ruff`/`mypy` без помилок; `node --check` для JS; 72 тести проходять.

## [2.3.1] - 2026-08-06

### 🔒 Security audit fixes (round from 2026-08-06)

#### Безпека (критичне)
- **Stored XSS у дашборді.** Назви дискових томів (з `node_exporter`/`windows_exporter`) та `error_message` у списку серверів більше не підставляються в DOM без екранування — це закриває шлях до крадіжки JWT з `localStorage` (захоплення акаунта адміна).
- **Токен WebSocket прибрано з URL.** Автентифікація WS (`/api/v1/ws/metrics`) тепер відбувається через перше повідомлення `{"type":"auth","token":...}` — токен більше не потрапляє в логи проксі/серверів та Referer.
- **`must_change_password` нарешті примушується.** Користувачі з прапорцем (перший запуск, скидання адміном) блокуються на всіх ендпоінтах, окрім `/auth/me` і `/auth/change-password`; додано UI-флоу зміни пароля на дашборді.
- **Режим Maintenance тепер працює.** Вузли в maintenance більше не генерують сповіщення (Server Down/Restored, High CPU, правила алертингу).
- **`/metrics` повертає Prometheus-формат.** Endpoint віддає `text/plain; version=0.0.4` замість JSON-рядка — Prometheus-скрейп знову коректний.

#### Безпека (середнє)
- `JWT_SECRET` коротший за 32 символи — попередження при старті.
- Пароль адміна з `reset-admin` поважає кастомний `auth.admin_username` (раніше жорстко `'admin'`).
- `create_user`/`update_user` використовують Pydantic-моделі замість `bool("false")` (type confusion).
- `force_scrape` тепер лише для адмінів; валідація `create_service` (name/check_type/interval/timeout).
- SMTP: підтримка `use_tls` (SMTPS/465); системні логи читаються з `LOG_DIR`.

#### Виправлено
- **Бекапи консистентні.** Запис через SQLite online-backup API (раніше `shutil.copy2` у WAL-режимі мовчки втрачав останні дані).
- **Retention для таблиці `metrics`** (push-метрики більше не ростуть безкінечно).
- **Правила алертингу:** враховуються `condition` (less_than/greater_than) і `duration` (debounce без спаму); шаблони `{{ value }}`/`{{ server }}` підставляються; правила типу `exporter_available` коректно пропускаються, а не мовчки ламаються.
- `_evaluate_cpu_alert` більше не злітає хибним алертом на першому скрейпі після рестарту.
- Windows-мережа: прибрано оманливий fallback на `windows_net_current_bandwidth_bytes` (rx=tx=capacity).
- Service latency chart: виправлено поле `latency_ms` (раніше JS читав неіснуюче `response_time`).

#### Продуктивність
- DNS-резолвінг SSRF-guard винесено з event-loop (`asyncio.to_thread`).
- Обмежено одночасність скрейпу/перевірок сервісів (Semaphore).
- bcrypt у `/auth/login` виконується в потоці, а не на event-loop.
- `_log_audit` логує збій запису аудиту замість мовчазного `pass`.

#### Чистота
- `ruff` та `mypy` — без помилок по всьому `pymon/`.
- Піновано `lucide@0.321.0` (раніше `@latest`); SW-кеш бампнуто.

## [2.2.0] - 2026-06-19

### 🔒 Посилення безпеки та аудит коду

#### Безпека (критичне)
- **Прибрано оборотне зберігання пароля адміна.** Видалено Fernet-шифрування пароля, друк пароля в консоль/лог при кожному старті та запис у `credentials.txt`. У БД тепер лише bcrypt-хеш; пароль показується **один раз** при створенні чи `reset-admin`.
- **Прибрано слабкий дефолтний пароль `291263` з коду.** За порожнього/слабкого значення на першому запуску генерується сильний випадковий пароль (можна задати через `PYMON_ADMIN_PASSWORD`).
- **Виправлено контроль доступу (broken access control).** Керування серверами (create/update/delete/maintenance), бекапи (`/backup/*`), очищення журналів аудиту/системних логів і метрик тепер вимагають адмін-прав.
- **API-ключі більше не дають адмін-доступу.** Ключ призначений лише для інжесту/читання — будь-які адмін-дії через `X-API-Key` повертають 403, незалежно від ролі власника.
- **Усунено збережений XSS у дашборді.** Усі дані серверів/сервісів/користувачів/журналів екрануються перед вставкою в DOM; хост сервера валідовується суворим whitelist-ом символів.
- **SSRF-захист.** Скрейп/перевірки сервісів відмовляють на адреси cloud-метаданих (`169.254.169.254` тощо); вимикається через `PYMON_ALLOW_METADATA=true`. Приватні LAN-діапазони лишаються дозволеними (це сенс застосунку).
- **Безпечне відновлення з бекапу.** `/backup/restore` використовує онлайн-backup API SQLite замість перезапису файлу живої БД (без ризику пошкодження під WAL).

#### Виправлено
- Витік зʼєднань SQLite в `_log_audit` (додано `finally`).
- Латентний баг: route-аліаси історії передавали обʼєкт `Depends` замість користувача — винесено спільний хелпер `_server_history`.
- Парсинг Prometheus-лейблів ламався на значеннях, що містять `}` (використано `rindex`).
- `_parse_duration` коректно обробляє дробові значення.
- Видалення сервера тепер прибирає й повʼязані `alerts` (без сиріт).
- `last_login` оновлюється при вході.
- Парсер cron бекапу більше не падає на `*/15`, `2,14`, `1-3` (раніше `int(hour)` кидав виняток і бекап мовчки не виконувався).
- `reset-admin` визначає шлях до БД так само, як сервер (`DB_PATH` або `config.yml`), тож редагує саме живу базу.

#### Змінено / Продуктивність
- Усунено N+1 запити в агрегованій історії, експорті всіх серверів і порівнянні метрик (один згрупований запит замість запиту-на-сервер).
- Прибрано дублювання: спільні `TIME_RANGES` (`pymon/constants.py`) і `build_channels` (`pymon/notifications.py`).
- `request_id` в middleware — `uuid4` замість `id(request)`.
- Прибрано CLI-команди `show-password`/`restore-password`; замість них — `reset-admin`.
- Видалено тимчасові скрипти з кореня репозиторію.

#### Аудит (раунд 4) — додаткове посилення
- **API-ключі більше не можуть змінювати конфігурацію.** Створення/видалення алертів і сервісів тепер вимагає адмін-прав (`get_admin_user`), як і керування серверами/налаштуваннями — раніше будь-який key/не-адмін міг їх змінювати.
- **SSRF-guard переписано.** Замість блокліста з 3 рядків хост резолвиться, нормалізуються альтернативні кодування IP (десяткове/hex/octal), і відмова спрацьовує для метаданих, loopback, link-local (`169.254.0.0/16`, `fe80::/10`), multicast. Приватні LAN-діапазони лишаються дозволеними.
- **Блокуючий I/O сповіщень винесено з event-loop.** `dispatch()` (httpx/SMTP) виконується через `asyncio.to_thread`; додано timeout для SMTP — повільний канал більше не стопорить скрейп.
- **Security-заголовки** на кожній відповіді: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Content-Security-Policy`, HSTS (через HTTPS).
- **`export_config` редагує секрети** (паролі, токени, webhook-URL, auth-заголовки) перед поверненням.
- **Коректний uptime %.** Простій тепер фіксується рядком у `metrics_history` (раніше графік завжди показував ~100%).
- `jwt_expire_hours` з конфігу нарешті застосовується (раніше час життя токена був жорстко 24 год).
- Єдина політика складності пароля для створення/зміни/скидання (раніше створення перевіряло лише довжину).
- Виправлено витоки зʼєднань SQLite (`import-prometheus`, cleanup/VACUUM) через `try/finally`; невалідний YAML повертає 400, а не 500.
- SSL-термін: порівняння у UTC (раніше зміщення на офсет таймзони).
- WebSocket-broadcast ітерує копію списку (без гонки при паралельних розсилках); fire-and-forget push-таск тримає сильне посилання.
